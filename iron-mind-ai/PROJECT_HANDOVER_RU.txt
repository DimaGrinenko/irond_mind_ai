ЧАСТЬ A. КАК РАССКАЗАТЬ НА ЗАЩИТЕ (5–7 минут)
══════════════════════════════════════════════════════════

1. Вступление (30 сек)
   «Iron Mind AI — мобильное фитнес-приложение с сервером. Пользователь
   выбирает программу, записывает тренировки, видит аналитику прогресса и
   общается с AI-тренером. Стек: NestJS + PostgreSQL + Prisma на backend,
   Expo React Native на клиенте.»

2. Архитектура (1 мин)
   «Клиент ходит в REST API по JWT. Данные в PostgreSQL. Бизнес-логика в
   модулях NestJS: программы, тренировки, питание, статистика, чат.
   На телефоне — вкладки: Главная, Программы, AI, Аналитика, Профиль.»

3. Живое демо — рекомендуемый порядок (3–4 мин)
   а) Запуск: Postgres → backend :4001 → Expo (см. D:\iron\ЗАПУСК_ПРИЛОЖЕНИЯ.txt).
   б) Вход: user@ironmind.local / user12345
   в) Программы: открыть шаблон (Фулбади / PPL), «Использовать программу».
   г) Главная: старт тренировки дня → Gym Mode → подходы → завершить.
   д) Аналитика: графики, объём, нагрузка по мышцам.
   е) AI: вкладка AI — статус «Живой AI · OpenRouter», написать вопрос в поле
      внизу (не только кнопки-подсказки), показать ответ.
   ж) Профиль → Тренировки: история с нормальными названиями упражнений,
      удаление тестовой записи (корзина).

4. AI — что сказать комиссии (1 мин)
   «AI подключён через OpenAI-совместимый API на backend (сейчас OpenRouter,
   модель deepseek/deepseek-chat). Ключ только на сервере, не в приложении.
   Чат хранится в БД по пользователю. Если API недоступен — срабатывают
   локальные шаблонные ответы (fallback). В профиле «Тренер» — тот же чат.»

5. Что доработано недавно (30 сек)
   «Починили аналитику на битых данных, убрали колесо удачи, подключили
   реальный AI, исправили историю тренировок и добавили удаление записей.»

6. Ограничения честно (20 сек)
   «Соцсеть/дуэли — заготовка UI. Подписка — экран-заглушка. Живой человек-
   тренер в очереди — пока AI. Для продакшена нужны тесты, health-check, CI.»

7. Заключение (20 сек)
   «Полный цикл: регистрация → программа → тренировка → аналитика → AI.
   Проект воспроизводим по инструкции запуска, готов к демонстрации.»

ЧАСТЬ B. НАЗНАЧЕНИЕ И ЦЕЛЕВАЯ АУДИТОРИЯ
══════════════════════════════════════════════════════════

Iron Mind AI — персональный фитнес-ассистент для силовых тренировок.

Задачи для пользователя:
- выбрать и вести программу (шаблоны: фулбади, сплиты, PPL, цели mass/relief);
- записывать подходы в режиме зала (Gym Mode);
- видеть прогресс: объём, калории, вес, нагрузка по мышцам;
- получать советы от AI-тренера в чате;
- геймификация: достижения, «листья», магазин косметики.

ЧАСТЬ E. РЕАЛИЗОВАННЫЙ ФУНКЦИОНАЛ (для отчёта)
══════════════════════════════════════════════════════════

Авторизация и онбординг:
  - регистрация, логин, JWT в AsyncStorage;
  - онбординг: цель, антропометрия, расчёт КБЖУ, создание аккаунта;
  - демо-пользователь: user@ironmind.local / user12345 (seed).

Программы:
  - каталог шаблонов с днями и упражнениями;
  - карточки целей (mass, relief) отдельным блоком;
  - клонирование, редактор, «Использовать» → расписание в календаре.

Тренировки:
  - Gym Mode: подходы, вес, повторы, отдых, заметки, голос (web);
  - синхронизация с backend (exerciseSlug → id в БД);
  - история: Профиль → Тренировки;
  - удаление тренировки: DELETE /workouts/:id, кнопка корзины.

Аналитика:
  - GET /stats/me?days=7|30;
  - метрики, график, muscle load;
  - устойчивость к «битым» связям exercise в старых данных.

AI-тренер:
  - вкладка AI: чат, поле ввода, быстрые вопросы;
  - GET /chat/status — «Живой AI · OpenRouter» (или fallback);
  - POST /chat — ответ LLM + история в БД;
  - Профиль → «Тренер» — тот же API.

Прочее:
  - питание, замеры, фото прогресса, календарь;
  - достижения / дерево прогресса;
  - экономика (листья, магазин);
  - роли: USER, COACH, ADMIN (панели coach/admin);
  - локализация RU/EN.

Убрано по требованию:
  - Daily Wheel (колесо) с главного экрана.

ЧАСТЬ J. ВОЗМОЖНЫЕ ВОПРОСЫ КОМИССИИ — КРАТКИЕ ОТВЕТЫ
══════════════════════════════════════════════════════════

В: Почему Expo, а не нативный Swift/Kotlin?
О: Быстрая кроссплатформенная разработка, один код для iOS/Android/Web-демо.

В: Где хранятся пароли?
О: bcrypt-хеш в PostgreSQL, JWT для сессии, секреты в .env.

В: Как масштабировать AI?
О: Ключ на сервере, лимиты по пользователю/тарифу, очередь сообщений, кэш.

В: Что если сервер недоступен?
О: Логин не проходит; AI — шаблоны или ошибка сети; часть UI — локальный SQLite.

В: Чем отличается от MyFitnessPal?
О: Фокус на силовых программах, gym mode, AI-тренер, дерево достижений, не только калории.

В: Безопасность API-ключа OpenRouter?
О: Только backend/.env, не в mobile, не в git; для сдачи — отдельный ключ с лимитом.

ЧАСТЬ L. ИТОГ ДЛЯ ЗАКЛЮЧЕНИЯ В ОТЧЁТЕ
══════════════════════════════════════════════════════════

Разработан fullstack-продукт Iron Mind AI: мобильный клиент (Expo/React Native)
и сервер (NestJS/PostgreSQL/Prisma) с JWT-авторизацией. Реализованы программы
тренировок, режим зала, аналитика прогресса, питание и замеры, геймификация
и интеграция AI-тренера через внешний LLM API (OpenRouter) с серверным
хранением диалога. Устранены критические дефекты (аналитика, отображение
истории, UX чата и программ). Проект воспроизводим локально, подготовлены
инструкции запуска и демонстрации для защиты.
